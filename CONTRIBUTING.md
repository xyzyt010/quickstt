# Contributing to QuickSTT

Thanks for helping improve QuickSTT.

## Project Goals

QuickSTT aims to be:
- practical for end users
- modular for contributors
- transparent about tradeoffs
- friendly to commercial and open use

## How to Contribute

- Report bugs with reproducible steps
- Suggest improvements with specific user impact
- Submit focused pull requests
- Keep changes small when possible
- Include testing notes in every PR

## Development Expectations

- Preserve existing user workflows unless intentionally changed
- Prefer native, maintainable, documented solutions
- Avoid breaking release/distribution paths while improving internals
- Be explicit about platform assumptions and hardware requirements

## Pull Request Guidance

- Explain what changed and why
- Mention risk areas and migration impact
- Include screenshots for UI changes when possible
- Note whether the change affects:
  - `QuickSTT.exe`
  - `QuickSTT_App.exe`
  - `stt_service.exe`
  - `QuickSTT_Server_App.exe`

## Areas Where Help Is Valuable

- macOS desktop support
- Linux packaging and runtime compatibility
- GPU runtime packaging
- cloud provider integrations
- wakeword accuracy and runtime efficiency
- release engineering and GitHub automation
